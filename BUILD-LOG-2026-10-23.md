# Build log — 2026-10-23, round 1

Internal log of what shipped this round against the backlog in `PLAN-2026-10-23-DEEP.md` /
`STRATEGY-2026-10-23.md`. Terse, points at the actual code.

## Shipped this round

### 1. Client-side Gmail direct-send (backlog #1)
`index.html`: new "4. Connect Gmail" panel. Google Identity Services OAuth2 token client,
`gmail.send` scope only. Token lives in `sessionStorage` + an in-memory variable — never sent to
`api/yc.py`. MIME message built client-side (`mimeEncodeHeader`/`b64urlFromString`) and POSTed
straight to `https://gmail.googleapis.com/gmail/v1/users/me/messages/send`. Persisted send queue
(`localStorage["yc-outreach-v2-queue"]`) with a visible pending/sent-today/next-send countdown, a
20–60s randomized delay between sends (`startQueueWorker`), and a configurable daily cap (default
30, rolling 24h window via `yc-outreach-v2-sendlog`). Draft actions show a "➤ Send" button instead
of "Copy body" once connected, falling back to Copy when not. A successful send auto-advances the
company's pipeline stage (see #6).
**Owner-only step, not done, noted inline in code**: `GOOGLE_CLIENT_ID` in `index.html` is a
placeholder (`REPLACE_WITH_...`). Needs a free OAuth 2.0 Web application client from
<https://console.cloud.google.com/apis/credentials> (enable Gmail API, add this origin to
"Authorized JavaScript origins"). Zero cost, console-only. Until set, "Connect Gmail" shows a clear
inline message and every other feature (Copy/mailto) works exactly as before — verified live.

### 2 + 13. Job-aware personalization + job-description endpoint (backlog #2, #13)
`api/yc.py`: new `action=job&url=<ycombinator.com job url>` route. `JOB_URL_RE` restricts it to
`ycombinator.com/companies/<slug>/jobs/<id>` (same allowlist spirit as the rest of this file — never
an open proxy). `job_detail()` fetches the job's own page and parses `props.job` out of the
`data-page` JSON: full `description`, `interview_process`, `location`, `salary_range`,
`equity_range`, `min_experience`, `visa`, `skills`. Verified against a real live job
(`stripe/jobs/jdBhPmD-...`) — returns the full role description.
`index.html`: `{job_title}`/`{job_url}` added to the placeholder set (now 10) and wired into
`fill()`. When a company has >1 open role, a per-company role-picker `<select>` (`jobPicker()`)
appears, sticky per-slug in `localStorage["yc-outreach-v2-jobsel"]`, and the draft retargets live.
Each job title is also a button that lazily fetches and caches (`yc-outreach-v2-jobcache`) the full
description inline.

### 3. Confidence-ranked, Apify-free email resolution (backlog #3)
`api/yc.py`:
- `resolves_mx(domain)`: DNS-over-HTTPS against Cloudflare's resolver (stdlib `urllib`, no
  dnspython) — returns `True`/`False`/`None` (lookup inconclusive). Detects the RFC 7505 null-MX
  case (`example.com`'s `"0 ."` record) as "no mail server", not just an absent MX. Verified live:
  `stripe.com`→True, `example.com`→False, a nonexistent domain→None.
- `founders()` now only offers guesses when `mx is not False`, and scales confidence down 25% when
  the MX lookup itself was inconclusive instead of blocking guesses outright.
- `guesses()` returns `[{email, pattern, confidence}]` instead of a flat string list. Confidence
  numbers come straight from this project's own published benchmark (README: first guess right 80%
  of the time, right answer somewhere in the list 93% of the time) → `{first:80, first.last:7,
  flast:4, firstlast:2}`.
- `infer_pattern()` + `apply_inferred_pattern()`: once any founder's real email (site-scraped) is
  known for a company, every other founder at that domain gets re-ranked to that same pattern first
  at 95% confidence. Unit-verified directly against the module.
`index.html`: `best()` carries confidence through for every source (verified 99%, unverified 60%,
on-site 97%, guess per the server's number); rendered as a `NN%` badge next to every email, plus a
collapsible "other guesses" line showing the remaining candidates with their own percentages.

### 4 + 6. Pipeline stages + follow-up sequencing (backlog #4, #6)
`index.html`: replaced the old boolean `sent` `Set` (commit `bfca064`) with a full stage enum per
slug — `not_sent / sent / followed_up / replied / interview / rejected / closed`, each carrying its
own timestamp (`stages[slug] = {stage, sentAt, followupDueAt, followedUpAt, repliedAt, ...}` in
`localStorage["yc-outreach-v2-stages"]`). One-time migration on load folds the old `-sent` Set into
the new shape. Marking "Sent" auto-schedules `followupDueAt` = `addBusinessDays(now, N)` (default 5,
configurable). A second template pair (`followup_subject`/`followup_body`, own editor under a
`<details>` in the template section) generates a shorter second-touch draft once a contact is
`sent`/`followed_up`, with its own Copy/Send action. Toolbar gained a stage filter dropdown
(including a derived "Follow-up due" value) and the "shown" summary now reports contacted/due
counts. CSV export gained Stage/Sent-At/Follow-up-Due/Followed-Up-At/Replied-At columns.
Both existing regression tests (`tests/test_sent_tracking.mjs`, `tests/test_industry_filter.mjs`)
were updated to drive the new stage `<select>` instead of the removed checkbox and to stub the two
new browser globals the script now touches at load (`sessionStorage`, `setInterval`) — both still
pass, same slug-isolation guarantee as before.

### 7 + 14. New-batch / new-role watcher (backlog #7, #14)
`api/yc.py`: new `action=digest&known_batches=<json>&slugs=<csv>&known_jobs=<json>` route.
`company_jobs_quick()` is a cheap job-count-only fetch (no website scrape) so up to
`MAX_DIGEST_SLUGS=40` companies can be checked in one round trip; the route always returns the full
current batch list (`batches`) plus `job_counts` for every checked slug, not just the diffs, so the
client can refresh its whole baseline from one call. Verified live end-to-end.
`index.html`: `setInterval` + Page Visibility API poll every 5 minutes while the tab is visible
(and immediately on becoming visible again), comparing against `localStorage` baselines
(`-lastbatches`, `-lastjobs`) primed on first load so it never spams on the very first run. Fires a
real `Notification` (after "Enable alerts" grants permission) plus a status line, for both new
batches and new job postings on already-loaded companies. Fully client-side, no new backend state.

### 8. Fit-score ranking (backlog #8)
`index.html`: new "Your skills / stack" field in step 1, persisted. `fitScore()` tokenizes the
skills text and overlaps it against a company's open-role titles (always available) plus any job
descriptions already fetched via #2/#13 (`jobCache`), as % of skill keywords matched. Rendered as a
`NN% fit` badge on the card; a "Best fit first" toolbar button re-sorts the visible list by it.
Verified live (50% fit on titles alone, 100% once the fetched description text was included).

### 9. Multi-batch search (backlog #9)
`api/yc.py`: `companies()` now fans a comma-separated batch list out in parallel
(`companies_one()` per batch) and de-dupes by slug; `route()` validates each batch name and caps
the list at `MAX_BATCHES=8`.
`index.html`: batch `<select>` is now `multiple`; `loadBatch()` reads every selected option, joins
them into one cache key, and passes the list straight through. Verified live loading two batches
(Summer 2027 + Winter 2027) in one pass, 6/6 companies.

### 11. Full session export/import (backlog #11)
`index.html`: "Export session" dumps every `localStorage` key prefixed `yc-outreach-v2` (profile,
templates, loaded batches, stages, job cache/selection, queue, settings — generic prefix scan, not
a hardcoded list, so it can't silently miss a future key) into one timestamped JSON file. "Import
session" (hidden file input behind a label) restores them after a confirm, then reloads. Verified
live: exported, cleared `localStorage`, re-imported, pipeline-stage data for a marked-sent company
came back exactly.

## Found and fixed along the way (not on the original backlog)
- **Real bug, caught in browser testing**: `filter()` / "Expand all" / CSV export all used
  `document.querySelectorAll("details")` with no scope. Adding the new follow-up-template
  `<details>` disclosure in the template editor (item 4) made that selector match an extra,
  data-less element, breaking the "N shown" count (`8 of 7 shown`) and the CSV's visible-row
  selection. Fixed by scoping all three to `#list details`. Caught by actually running the app in a
  real browser (`gstack`/`browse`), not by reasoning about the diff.
- `label.btn` (the new "Import session" control) wasn't covered by the `button,a.btn{...}` CSS
  selector and would have rendered unstyled; added `label.btn` to the rule.
